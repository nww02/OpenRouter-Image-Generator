# AI Image Generator — Avalonia Application Specification

> **Project:** Avalonia 12.1.2 desktop application for AI image generation via OpenRouter
> **Language:** C# / .NET 10.0
> **Build:** Microsoft.NET.Sdk / NuGet
> **Starting Scaffold:** Basic Avalonia project with Program.cs, App.axaml, App.axaml.cs, MainWindow.axaml, MainWindow.axaml.cs

---

## 1. Overview

A multiple-document interface (MDI) desktop application that allows users to generate images using OpenRouter-hosted AI image-generation models. The user can have multiple "image document" windows open simultaneously, each with its own generation history, canvas, prompt, and model parameters. Each window carries its own copy of the generation model — override it per-window without affecting the default. The application discovers model parameters from the API at runtime (resolutions, aspect ratios, quality levels, etc.) and builds a per-window settings panel from them. It supports saving/loading images with companion prompt metadata, browsing available models via the OpenRouter API, and includes an AI-assisted prompt generator.

### 2.2 Key Design Patterns

| Concern | Pattern |
|---------|---------|
| MDI with floating windows | **Primary:** `Dock for Avalonia` (NuGet: `Dock.Avalonia`, `Dock.Model`) with `DockSettings.UseManagedWindows = true` for **true in-app free-floating MDI**. Each document is a managed window with its own draggable titlebar — can be moved **anywhere** within the main window's client area (not just docked to edges). Supports: free positioning, minimize/maximize/close buttons on titlebar, window cascading/tile, tab groups when docked together, z-order management. This is classic MDI (like old WinForms MDI or Visual Studio 2005). |
| Async API calls | `async Task` / `await` with `HttpClient`. No blocking `.Result`/`.Wait()`. UI updates happen naturally via CommunityToolkit property changes. |
| Preferences persistence | JSON file via `System.Text.Json` in platform app data folder: `Environment.GetFolderPath(Environment.SpecialFolder.ApplicationData) + "/ImageGenerator/preferences.json"`. |
| ViewModel structure | `MainWindowViewModel` holds a `DockFactory` which manages `ImageDocumentViewModel` instances as MDI documents. Each image window has its own `ObservableCollection<GenerationRecordViewModel>` history and `ObservableCollection<ModelParameterValue>` for parameters. |
| Model parameter discovery | On model selection, the app calls `provider.GetModelParameterDescriptorsAsync()` to fetch the model's schema from the API. Descriptors (enum, range, boolean) are cached in preferences. Each window gets a deep copy. |
| Per-window model copy | Each `ImageDocumentViewModel` has its own `GenerationModel` property, copied from the configured default on creation. The Model Parameters dialog can override it per-window, re-fetching that model's parameter schema from the API. |
| Parameter save/restore | Generation records store the model name and parameter values (keyed by name). `.prompt` sidecar files persist them. On load, the window adopts the sidecar's model and restores the values onto that model's schema. |
| Unsaved tracking | Each `ImageDocumentViewModel` has `bool IsDirty` property; DockFactory checks all VMs before closing a document or quitting. |
| Status bar | Live updates: account balance (refreshed on startup and after each billable request), open window count, session spend total. Costs from all operations (image gen, prompt building, vision analysis) aggregate into a single session counter that resets on program load. |
| History tooltips | Hover any thumbnail to see: timestamp, cost in USD, model name, and first 200 chars of the prompt. |
| MVVM | `CommunityToolkit.Mvvm` (NuGet) for `ObservableObject`, `[ObservableProperty]`, `[RelayCommand]`, `[AsyncRelayCommand]` |

## 3. Detailed Component Specifications

### 3.1 MainWindow (MainWindow.axaml / MainWindow.axaml.cs)

**Responsibilities:**
- Owns the `DockControl` from `Dock.Avalonia` which serves as the MDI container
- Uses `DockFactory` (in ViewModels/) to manage layout — creates document windows via `DocumentDock` with `LayoutMode = DocumentLayoutMode.Mdi`
- MainWindowViewModel handles menu actions (Load, Quit, New Image, Preferences, About)
- Status bar at the bottom: balance, window count, session spend (all bound to MainWindowViewModel)
- On Quit: DockFactory iterates all documents, if any `IsDirty`, shows confirmation asynchronously
- On Load: creates new document via DockFactory, loads image+metadata, adds to layout
- Window title: `"AI Image Generator"`
- Configure `DockSettings.UseManagedWindows = true` and `DockSettings.EnableWindowMagnetism = true` at startup (in App.axaml.cs)

**DockFactory (not a separate Window class — the ViewModel owns the dock):**
- `DockFactory` extends `Dock.Model.Mvvm.Factory` and implements `CreateLayout()`, `AddDocument()`, `CloseDockable()`
- Creates a `DocumentDock` with `LayoutMode = DocumentLayoutMode.Mdi`
- Each image document is a `Document` (from `Dock.Model.Mvvm.Controls`) wrapping an `ImageDocumentViewModel`
- Documents are free-floating managed windows with draggable titlebars, minimize/maximize/close buttons
- Supports tab groups, z-order management, and window magnetism
- Each document gets: per-window model copy (from preferences default), parameter schema population, minimum window size (560×400), and cost-report wiring to the status bar
- Loaded images with a different model get their schema fetched from the API before parameters are restored (`LoadSchemaAndRestoreAsync`)
- DockFactory fires `SessionCostAdded` and `WindowCountChanged` events consumed by MainWindowViewModel's status bar

**MainWindowViewModel:**
- Owns the DockFactory instance; builds the layout on construction
- Creates one blank image document on startup
- Fetches the configured model's parameter schema on first load (`EnsureModelParametersAsync`) and caches it in preferences
- Handles `RefreshBalanceAsync()`: fetches account credit from OpenRouter on startup and after every billable request
- Handles preferences save: copies all fields back, re-fetches parameter schema if the generation model changed
- Applies theme immediately on Save

### 3.2 Image Document View (ImageDocumentView.axaml / .axaml.cs)

**Location:** `Views/Documents/ImageDocumentView.axaml` and `.axaml.cs`
This is a **UserControl** (not a Window) that serves as the content of each MDI document. Hosted inside a `DocumentDock` from `Dock.Model`.

**Layout (AXAML) — key structure:**
- 2-column grid (180px history | * canvas+controls), 3 rows (3* canvas | Auto splitter | 1* controls panel)
- History panel (left, spans all rows): `ScrollViewer` → `ItemsControl` → vertical `StackPanel` of thumbnails
  - Each item: a `Button` wrapping a `Border` (with `historyItem` class, selected has `DodgerBlue` border) → `Image` (160px wide) + `TextBlock` timestamp
  - ToolTip: bound to `TooltipText` (shows timestamp, cost, model, prompt excerpt)
  - Click: `RestoreRecordCommand` with `CommandParameter="{Binding}"`
- Canvas (top-right): `Grid` containing `Border`(black background) + `Image`(Stretch=Uniform) + loading overlay (`ProgressBar` + "Generating..." text, visible when `IsGenerating`)
- Splitter (middle-right): `GridSplitter` with `ResizeDirection="Rows"`, `ResizeBehavior="PreviousAndNext"`
- Controls panel (bottom-right): `Grid` with two rows (prompt `*` | buttons `Auto`)
  - Prompt: `TextBox` with `AcceptsReturn`, `TextWrapping="Wrap"`, placeholder "Enter your prompt here..."
  - Buttons row: `StackPanel` horizontal, right-aligned:
    - `"⋯"` button → `EditModelParametersCommand` (opens ModelParametersDialog)
    - `"Build Prompt"` → `GeneratePromptCommand`
    - `"Image->Prompt"` → `GeneratePromptFromImageCommand`
    - `"Prompt->Image"` → `GenerateImageCommand`
    - `"Save"` → `SaveImageCommand`

**Minimum window size:** 560×400 (set in DockFactory.AddDocument — 180px history + 320px canvas column + margins, and tall enough for titlebar + canvas + splitter + controls)

## 4. Provider-Agnostic API Architecture

The application uses a **provider abstraction** so users can use OpenRouter (default) or any OpenAI-compatible API (Ollama, LM Studio, LocalAI, custom endpoints).

### 4.1 Provider Abstraction

```csharp
// Interface for AI image generation providers
public interface IImageGenerationProvider
{
    string Name { get; }
    string BaseUrl { get; }
    bool RequiresApiKey { get; }

    // Model discovery
    Task<List<ProviderModelInfo>> ListModelsAsync(string? apiKey = null, CancellationToken ct = default);

    // Image generation
    Task<byte[]> GenerateImageAsync(string prompt, int width, int height, string model, string? apiKey, CancellationToken ct);

    // Chat completion (for prompt generation & image-to-prompt)
    Task<string> ChatCompletionAsync(List<ChatMessage> messages, string model, string? apiKey, CancellationToken ct);

    // Vision chat completion (image-to-prompt)
    Task<string> VisionChatCompletionAsync(string prompt, byte[] imageBytes, string model, string? apiKey, CancellationToken ct);
}

// Model info returned by provider
public class ProviderModelInfo
{
    public string Id { get; set; } = string.Empty;
    public string Name { get; set; } = string.Empty;
    public ModelCapabilities Capabilities { get; set; } = new();
    public ModelPricing? Pricing { get; set; }
}

public class ModelCapabilities
{
    public bool SupportsImageGeneration { get; set; }
    public bool SupportsVision { get; set; }
    public bool SupportsChat { get; set; }

    public List<string> SupportedAspectRatios { get; set; } = new();
}

public class ModelPricing
{
    public decimal? PerImage { get; set; }
    public decimal? PerMegapixel { get; set; }
    public decimal? PerToken { get; set; }
    public string? Currency { get; set; } = "USD";
}

public class ChatMessage
{

}

public class ChatImageContent
```

### 4.2 Provider Implementations

**OpenRouterProvider (default)** — Implements `IImageGenerationProvider`:
- BaseUrl: `https://openrouter.ai/api/v1`
- Uses OpenRouter-specific endpoints (`/images`, `/models` with image filter)
- Handles OpenRouter's specific response formats
- Adds required headers (`HTTP-Referer`, `X-Title`)

**OpenAICompatibleProvider (generic)** — For Ollama, LM Studio, LocalAI, etc.:
- BaseUrl: configurable (e.g., `http://localhost:11434/v1` for Ollama)
- Uses standard OpenAI-compatible endpoints (`/images/generations`, `/chat/completions`, `/models`)
- No special headers required
- Simpler model filtering (checks model capabilities from response)

## 5. OpenRouter API Reference (Default Provider)

### 5.1 API Base Configuration

- **Base URL:** `https://openrouter.ai/api/v1`
- **Authentication:** Bearer token via `Authorization: Bearer <api-key>` header
- **Referer header:** Required by OpenRouter — use `https://localhost/` or the app name
- **X-Title header:** `AI Image Generator` (identifies app to OpenRouter)
- **All calls** go through `OpenRouterProvider` which implements `IImageGenerationProvider`

### 5.2 List Models

**Endpoint:** `GET /v1/models`

This endpoint returns all available models. We filter client-side for models that support image generation (checking `model.supports.image_generation`) or vision (checking `model.supports.vision`).

**Response format (simplified):**
```json
{
  "data": [
    {
      "id": "stabilityai/stable-diffusion-3.5",
      "name": "Stable Diffusion 3.5",
      "architecture": { "modality": "text-to-image" },
      "pricing": { "image": 0.004 },
      "supports": { "image_generation": true, "vision": false }
    },
    ...
  ]
}
```

### 5.3 Image Generation

**Endpoint:** `POST /v1/chat/completions` (OpenRouter uses chat completion format for image gen)

OpenRouter uses the OpenAI-compatible chat completion format even for image generation. The generation model is specified in the model field.

**Request:**
```json
{
  "model": "stabilityai/stable-diffusion-3.5",
  "messages": [
    {
      "role": "user",
      "content": [
        { "type": "text", "text": "Generate an image of a cat on a train" }
      ]
    }
  ],
  "response_format": {
    "type": "image"
  }
}
```

**Alternative / preferred approach:** Some OpenRouter image models use the standard chat endpoint but return base64-encoded images in the response content, or use the `/v1/images/generations` endpoint (OpenAI-compatible).

**Response:**
```json
{
  "id": "gen-xxx",
  "choices": [
    {
      "message": {
        "content": "data:image/png;base64,iVBORw0KGgo...",
        "role": "assistant"
      }
    }
  ],
  "usage": { "cost": 0.004 }
}
```

The service extracts the base64 data, decodes it to bytes, and constructs an Avalonia `Image` object.

### 5.4 Chat Completion (for Prompt Generation & Image-to-Prompt)

**Endpoint:** `POST /v1/chat/completions`

**Request (Prompt Gen):**
```json
{
  "model": "openai/gpt-4o-mini",
  "messages": [
    {
      "role": "system",
      "content": "You are a creative prompt engineer. Generate a single, detailed image-generation prompt based on the following parameters. Output ONLY the prompt text, no introduction or explanation."
    },
    {
      "role": "user",
      "content": "Humour: Light-hearted\nStyle: Cartoon\nTopic: Trains\nColour: Vivid\nTime of Day: Morning\nMood: Joyful"
    }
  ]
}
```

**Request (Image-to-Prompt):**
```json
{
  "model": "openai/gpt-4o",
  "messages": [
    {
      "role": "user",
      "content": [
        { "type": "text", "text": "Describe this image in detail as a prompt for an image generation model." },
        { "type": "image_url", "image_url": { "url": "data:image/png;base64,iVBOR..." } }
      ]
    }
  ]
}
```

### 5.5 Pricing Retrieval

The model listing endpoint includes `pricing` for each model. For image models:
```json
"pricing": { "image": 0.004, "per_image": 0.004 }
```
For chat models:
```json
"pricing": { "prompt": 0.00001, "completion": 0.00004 }
```

These prices are shown in the ModelBrowserDialog as formatted strings.

## 5. User Interface Flows

### 5.1 New Image Flow
1. User clicks `Edit > New Image` (or `Ctrl+N`)
2. DockFactory instantiates a new `ImageDocumentViewModel`, copies the configured default generation model into it
3. Document appears as a free-floating managed window in the MDI container
4. Canvas shows black fill (no image yet)
5. Parameter schema is populated from preferences (model's cached descriptors); all values start unset (model defaults)
6. History panel is empty
7. Prompt textarea is empty

### 5.2 Generate Image Flow
1. User enters prompt into the prompt textarea
2. (Optional) User opens the Model Parameters dialog (⋯) to set resolution, aspect ratio, seed, etc.
3. User clicks `Prompt->Image`
4. Prompt->Image button is disabled while generating; a dimmed overlay with progress bar + "Generating..." text appears over the canvas
5. Provider called with: prompt, window's model (`GenerationModel`), window's parameter values (non-null only)
6. On success:
   - Response image decoded via `ImageUtils.BytesToBitmap()`
   - Actual output dimensions read from the decoded bitmap
   - A new `GenerationRecord` is created with image, prompt, model, parameters, cost, timestamp, dimensions
   - Record added to `History` list
   - Canvas updates to show the new image, thumbnail generated at 160px wide
   - `IsDirty` flag set to true, title updates (adds `*`)
   - `CostReported` event fires → forwarded to DockFactory → MainWindowViewModel updates `SessionSpent` and refreshes `CreditBalance`
   - All history items' `IsSelected` updated (only newest selected)
   - Generate button re-enabled, overlay hidden
7. On error:
   - Error dialog shown with descriptive message (API errors formatted by `ApiException.ToDisplayString()`)
   - Generate button re-enabled, overlay hidden

### 5.3 History Navigation Flow
1. User clicks a thumbnail in the left history panel
2. `ImageDocumentViewModel.RestoreRecord()` is called
3. Canvas displays the selected record's image
4. Prompt textarea is set to the record's prompt
5. Parameter values restored: `ApplyParameterValues()` sets each parameter from `record.Parameters`
6. All history items' `IsSelected` updated (only clicked item highlighted)
7. The selected thumbnail gets a `DodgerBlue` border (via `historyItem:selected` style selector)

### 5.3b Model Parameters Dialog Flow
1. User clicks the ⋯ button in any image window
2. `EditModelParametersAsync()` creates a `ModelParametersDialog` and calls `dialog.Initialize(this)`
3. The dialog opens as a modal window over the main window
4. Dialog shows:
   - Current model name (read-only textbox) with a ⋯ button to browse for a different model
   - Progress bar (visible during API fetch)
   - Parameter rows: each with a checkbox (mandatory params locked on), name, and editor (dropdown for enum, validated textbox for range/boolean)
5. Changing model via the ⋯ browse button:
   - Opens ModelBrowserDialog filtered to image gen models
   - On selection: `LoadParametersForModelAsync(newModel)` fetches that model's schema from the API
   - Old rows removed, new rows added with all values unset
6. On OK:
   - All rows validated (number ranges checked; out-of-bounds values show red error text)
   - If any row has a validation error, OK is blocked
   - On valid: each row commits its value back to the source `ModelParameterValue`
   - Dialog closes
7. On Cancel: all edits discarded, dialog closes

### 5.4 Save Flow

### 5.4 Save Flow
1. User clicks `Save`
2. If no current record or no image, the button is disabled (safe — bound to `HasCurrentImage`)
3. A `FilePickerSaveOptions` dialog opens with default filename `Generated-YYYYMMDD-HHmmSS.png`
4. User selects folder and confirms
5. Image is written as PNG to the chosen path
6. JSON metadata is written to `{filename}.png.prompt` containing:
   - `Prompt`: the prompt text
   - `Model`: the model that generated it (`GenerationModel` or record's model)
   - `Parameters`: non-null parameter values (keyed by name)
   - `Cost`: USD cost as reported by the API
7. The record's `IsSaved` flag is set to true
8. `IsDirty` is re-evaluated: if all records are saved, becomes false
9. Title updates (removes `*`)

### 5.5 Load Flow
1. User clicks `File > Load` (or `Ctrl+L`)
2. `FilePickerOpenOptions` dialog for `*.png` files
3. User selects a PNG file
4. Image bytes are read into memory
5. `ImageIOService.LoadImageWithMetadataAsync()` reads the companion `.prompt` file:
   - JSON sidecar: extracts Prompt, Model, Parameters (dictionary), Cost
   - Legacy plain-text `.prompt`: reads as plain prompt text (no model/params/cost)
6. `DockFactory.CreateLoadedImageDocument()` creates a new `ImageDocumentViewModel` and calls `LoadFromImage()`:
   - `GenerationRecord` created with loaded data (marked IsSaved=true)
   - Record placed in the window's history list, set as current
   - Prompt filled, image displayed
   - Window adopts the sidecar's model (if any) — `GenerationModel = record.Model`
   - Window queues parameter values for restoration (`_pendingParameterRestore`)
7. DockFactory.AddDocument() runs:
   - If the loaded model matches the configured default: parameters populated from cached schema, then pending values applied immediately
   - If the loaded model differs: schema fetched asynchronously from the API, pending values applied after the descriptors arrive (`LoadSchemaAndRestoreAsync()`)
8. Window added to MDI with minimum size 560×400

### 5.6 Quit Flow
1. User clicks `File > Quit` (or `Ctrl+Q` / window close button)
2. MainWindow iterates all `ImageDocumentViewModel` instances calling `IsDirty`
3. If any window has `isDirty == true`:
   - Modal confirmation dialog appears: "Unsaved images, really quit?" with [Yes] [No]
   - Yes → application exits
   - No → dialog dismissed, nothing happens
4. If no dirty windows, application exits immediately

### 5.7 Preferences Flow
1. User clicks `Edit > Preferences` (or `Ctrl+,`)
2. `PreferencesDialog` opens as a modal window
3. Fields (in layout order):
   - **Provider:** `ComboBox` with options **"OpenRouter"**, **"Ollama"**, **"LM Studio"**, **"LocalAI"**, **"Custom"** — selecting a non-OpenRouter provider shows the custom provider fields (Base URL, optional API key)
   - **Theme:** `ComboBox` with options **"Dark", "Light", "System"** (default: **"System"**). Changing the selection previews the theme immediately; **Save** commits it, **Cancel** reverts.
   - **API Key:** `TextBox` with `PasswordChar="•"` for masking
   - **Image Generation Model:** `TextBox` (read-only) + `[Browse...]` button
   - **Prompt Generation Model:** `TextBox` (read-only) + `[Browse...]` button
   - **Vision / Image Analysis Model:** `TextBox` (read-only) + `[Browse...]` button
4. `[Browse...]` buttons each open `ModelBrowserDialog` filtered to the appropriate model type (Image Gen / Vision / All Models)
5. When the generation model is changed, the app fetches that model's parameter schema from the API (`GetModelParameterDescriptorsAsync`) and stores it in the model parameters fields
6. `[Save]` / `[Cancel]` buttons at bottom
7. On **Save**: all preferences committed via `PreferencesService.Save()`:
   - If the generation model changed since the last save, `MainWindowViewModel.RefreshModelParametersAsync()` re-fetches the new model's parameter schema from the API before saving
   - Theme applied immediately via `App.ApplyTheme(theme)`
   - Dialog closes
8. On **Cancel**: changes discarded; previous theme restored; nothing written

**Theme handling details:**
- Theme value maps to Avalonia's `RequestedThemeVariant`: `"Dark"` → `ThemeVariant.Dark`, `"Light"` → `ThemeVariant.Light`, `"System"` → `ThemeVariant.Default` (follows the OS).
- The theme is applied on the application root (`Application.Current.RequestedThemeVariant`), so all windows, dialogs and MDI documents follow it.
- On startup the saved theme is loaded from the config file **before** the main window is created, so there is no flash of the wrong theme.
- The theme choice lives in the same config file as the rest of the preferences (see 6.1) and is persisted only when the user presses Save.

### 5.8 Model Browser Flow
1. Called from Preferences (Browse...) or Model Parameters dialog (⋯)
2. Opens as a modal resizable window with toolbar
3. Loading indicator while API call is in flight (first load, or when the user presses ⟳)
4. Toolbar:
   - **Search box**: live-filters by model name or ID as you type
   - **Filter dropdown**: "Image Gen", "Vision", "All Models" (pre-selected based on context)
   - **Free checkbox**: limit to free models only
   - **⟳ (refresh button)**: re-fetch the model list from OpenRouter
5. Results displayed in an `ItemsControl` with each row showing:
   - Model display name
   - Model ID (smaller, grey text)
   - Pricing (per image and/or per token) on the right, formatted
6. User can scroll through the list
7. Click a row to select it (highlighted), then `[Select]` or double-click to confirm
8. `[Cancel]` closes the dialog without changing the selection
9. If API call fails → error message shown; user can retry with the refresh button

## 6. Data Persistence

### 6.1 Preferences Storage

**Location:** Platform app data folder:
- `Environment.GetFolderPath(Environment.SpecialFolder.ApplicationData) + "/ImageGenerator/preferences.json"`
  - Linux: `~/.config/ImageGenerator/preferences.json`
  - Windows: `%APPDATA%\ImageGenerator\preferences.json`

**Format:**
```json
{
  "selectedProviderId": "openrouter",
  "openRouterApiKey": "sk-or-v1-...",
  "openRouterGenerationModel": "stabilityai/stable-diffusion-3.5",
  "openRouterVisionModel": "openai/gpt-4o",
  "openRouterPromptGenModel": "openai/gpt-4o-mini",
  "customProviderName": "Custom",
  "customProviderBaseUrl": "http://localhost:11434/v1",
  "customProviderApiKey": "",
  "customGenerationModel": "",
  "customVisionModel": "",
  "openRouterGenerationModelParameters": [ { "name": "resolution", "kind": "enum", "values": ["..."] }, ... ],
  "openRouterGenerationModelParametersFor": "stabilityai/stable-diffusion-3.5",
  "theme": "System"
}
```

- **`theme`** values: `"Dark"`, `"Light"`, or `"System"` (default when absent).
- **`openRouterGenerationModelParameters`**: cached model parameter schema, fetched from the API when the user picks a model via Browse. Avoids re-fetching on every startup.
- The file is written whenever the user presses **Save** in the Preferences dialog, and **only** then — no intermediate writes while editing.
- The API key is stored as plaintext in the JSON file (simple XOR/base64 obfuscation possible but not implemented).

### 6.2 Image Save Format

- Primary file: `Generated-YYYYMMDD-HHmmSS.png`
- Companion file: `Generated-YYYYMMDD-HHmmSS.png.prompt`
  - JSON sidecar containing the prompt, model, parameters and cost:
  ```json
  {
    "Prompt": "A whimsical cartoon of a train made of bread...",
    "Model": "bytedance-seed/seedream-5-5",
    "Parameters": { "resolution": "1024x1024", "n": "1" },
    "Cost": 0.004
  }
  ```
  - Legacy plain-text `.prompt` files (old app versions, prompt only) still load correctly.
  - On load, the window adopts the sidecar's model and restores saved parameter values onto that model's schema.

## 7. Threading & Concurrency

### 7.1 Async API Calls

All HTTP calls to OpenRouter must run off the UI thread:

```csharp
// Pattern for image generation — using AsyncRelayCommand (CommunityToolkit.Mvvm)
[AsyncRelayCommand]
private async Task GenerateImage()
{
    IsGenerating = true;

    try
    {
        // HttpClient is inherently async I/O — no need for Task.Run
        var imageBytes = await _openRouterService.GenerateImageAsync(
            _preferences.ApiKey,
            _preferences.GenerationModel,
            CurrentPrompt,
            ImageWidth,
            ImageHeight);

        // We're back on the UI thread — safe to update properties
        var record = new GenerationRecord
        {
            ImageData = imageBytes,
            Prompt = CurrentPrompt,
            Width = ImageWidth,
            Height = ImageHeight,
            Timestamp = DateTime.Now,
            IsSaved = false
        };

        History.Add(record);
        CurrentRecord = record;
        CurrentImageBytes = imageBytes;
        IsDirty = true;
    }
    catch (Exception ex)
    {
        // Show error dialog
        await _dialogService.ShowErrorAsync("Generation failed: " + ex.Message);
    }
    finally
    {
        IsGenerating = false;
    }
}
```

### 7.2 UI Thread Safety
- All UI mutations (updating canvas, history panel, text fields, button states) must go through `Avalonia.Application.Instance.InvokeLater()` or `Platform.RunLater()`
- Heavy image processing (thumbnail generation, base64 encode/decode) can stay on the background thread but must not touch UI objects
- Thumbnails: generate scaled-down versions of images on the background thread, then `InvokeLater` to update the history panel

## 8. Thumbnail Generation

To show thumbnails in the history panel:

```csharp
// Generate thumbnail from image bytes — off the UI thread
public static Bitmap? CreateThumbnail(byte[] imageBytes, int maxWidth = 120)
{
    try
    {
        using var ms = new MemoryStream(imageBytes);
        var bitmap = new Bitmap(ms);

        // Calculate scaled dimensions preserving aspect ratio
        double scale = (double)maxWidth / bitmap.PixelSize.Width;
        int thumbWidth = maxWidth;
        int thumbHeight = (int)(bitmap.PixelSize.Height * scale);

        // Create scaled bitmap (available on Avalonia Bitmap)
        return bitmap.CreateScaledBitmap(new PixelSize(thumbWidth, thumbHeight), BitmapInterpolationMode.HighQuality);
    }
    catch
    {
        return null; // Return null if thumbnail generation fails
    }
}
```

Thumbnails should be generated asynchronously after each generation completes, before updating the UI.

## 9. Unsaved Changes Tracking

Each `ImageWindow` tracks its dirty state:

```csharp
// In ImageWindowViewModel.cs
public partial class ImageWindowViewModel : ObservableObject
{
    [ObservableProperty]
    private bool _isDirty;

    // Called when a new generation is made
    private void OnGenerationCreated()
    {
        IsDirty = History.Any(r => !r.IsSaved);
    }

    // Called when the user saves the current record
    public void MarkSaved()
    {
        if (CurrentRecord != null)
        {
            CurrentRecord.IsSaved = true;
            // Re-check: if all records are saved, IsDirty = false
            IsDirty = History.Any(r => !r.IsSaved);
        }
    }
}

// In MainWindowViewModel.cs
public bool HasUnsavedWindows()
{
    return _openViewModels.Any(vm => vm.IsDirty);
}
```

## Appendix B: Key Avalonia API References

| Component | Avalonia Class / Pattern |
|-----------|--------------------------|
| Window | `Window` (from Avalonia.Controls) |
| Modal dialog | `window.ShowDialog<TReturn>(owner)` |
| Menu bar | `<MenuBar>` with `<MenuItem>` items |
| Text input | `TextBox` (single line), `TextBox AcceptsReturn="True"` (multi-line) |
| Buttons | `Button` |
| Image display | `Image` control with `Source` bound to `Bitmap` |
| Bitmap loading | `new Bitmap(stream)` or `new Bitmap(filePath)` |
| Image from bytes | `new MemoryStream(bytes)` → `new Bitmap(stream)` |
| Scroll panel | `ScrollViewer` |
| Vertical layout | `StackPanel` (or `ItemsControl` with `StackPanel` ItemsPanel) |
| Grid layout | `<Grid>` with `RowDefinitions` and `ColumnDefinitions` |
| File open dialog | `TopLevel.StorageProvider.OpenFilePickerAsync(options)` |
| File save dialog | `TopLevel.StorageProvider.SaveFilePickerAsync(options)` |
| Dropdown | `ComboBox` |
| List with columns | `DataGrid` (install `Avalonia.Controls.DataGrid` NuGet) |
| Password input | `TextBox PasswordChar="•"` (or any char) |
| Floating MDI | **Primary:** `Dock.Avalonia` + `Dock.Model` NuGet with `DockSettings.UseManagedWindows = true` — in-app free-floating managed windows with draggable titlebars. **Alt:** Separate `Window` instances via `window.Show()` (modeless) |
| Async UI dispatch | `Dispatcher.UIThread.InvokeAsync(action)` (from background) |
| Background thread | `await Task.Run(work)` or `await HttpClient.GetByteArrayAsync(...)` (naturally async) |
| Observable collections | `ObservableCollection<T>` (from System.Collections.ObjectModel) |
| MVVM | CommunityToolkit.Mvvm: `ObservableObject`, `[ObservableProperty]`, `[RelayCommand]`, `[AsyncRelayCommand]` |
| Application base path | `Environment.GetFolderPath(Environment.SpecialFolder.ApplicationData)` |
