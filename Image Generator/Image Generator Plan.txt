# AI Image Generator — Avalonia Application Specification

> **Project:** Avalonia 12.1.2 desktop application for AI image generation via OpenRouter
> **Language:** C# / .NET 10.0
> **Build:** Microsoft.NET.Sdk / NuGet
> **Starting Scaffold:** Basic Avalonia project with Program.cs, App.axaml, App.axaml.cs, MainWindow.axaml, MainWindow.axaml.cs

---

## 1. Overview

A multiple-document interface (MDI) desktop application that allows users to generate images using OpenRouter-hosted AI image-generation models. The user can have multiple "image document" windows open simultaneously, each with its own generation history, canvas, prompt, and dimension controls. The application supports saving/loading images with companion prompt files, browsing available models via the OpenRouter API, and includes an AI-assisted prompt generator.

### 2.2 Key Design Patterns

| Concern | Pattern |
|---------|---------|
| MDI with floating windows | **Primary:** `Dock for Avalonia` (NuGet: `Dock.Avalonia`, `Dock.Model`) with `DockSettings.UseManagedWindows = true` for **true in-app free-floating MDI**. Each document is a managed window with its own draggable titlebar — can be moved **anywhere** within the main window's client area (not just docked to edges). Supports: free positioning, minimize/maximize/close buttons on titlebar, window cascading/tile, tab groups when docked together, z-order management. This is classic MDI (like old WinForms MDI or Visual Studio 2005). |
| Async API calls | `async Task` / `await` with `HttpClient`. No blocking `.Result`/`.Wait()`. Return to UI thread via `Dispatcher.UIThread.InvokeAsync()` when needed from background threads. |
| Preferences persistence | JSON file via `System.Text.Json` in platform app data folder: `Environment.GetFolderPath(Environment.SpecialFolder.ApplicationData) + "/ImageGenerator/preferences.json"`. |
| Model data / state | `ObservableCollection<ImageWindowViewModel>` held in MainWindowViewModel; each ImageWindow has its own `ObservableCollection<GenerationRecord>` history. |
| Unsaved tracking | Each `ImageWindowViewModel` has `bool IsDirty` property; MainWindow iterates all VMs before quit. |
| MVVM | Use `CommunityToolkit.Mvvm` (NuGet) for `ObservableObject`, `[ObservableProperty]`, `[RelayCommand]`, `[AsyncRelayCommand]` |

### 2.3 Dependency Additions (csproj)

```xml
<!-- MVVM toolkit for clean ViewModel pattern -->
<PackageReference Include="CommunityToolkit.Mvvm" Version="8.4.0" />

<!-- MDI Docking library - required for managed windows MDI -->
```

## 3. Detailed Component Specifications

### 3.1 MainWindow (MainWindow.axaml / MainWindow.axaml.cs)

**Layout (AXAML):**
```xml
<Window xmlns="https://github.com/avaloniaui"
        xmlns:x="http://schemas.microsoft.com/winfx/2006/xaml"
        xmlns:dock="clr-namespace:Dock.Avalonia.Controls;assembly=Dock.Avalonia"
        xmlns:dockModel="clr-namespace:Dock.Model.Controls;assembly=Dock.Model"
        x:Class="Image_Generator.MainWindow"
        Title="AI Image Generator">

    <DockPanel>
        <!-- Main Menu Bar -->
        <Menu DockPanel.Dock="Top">
            <MenuItem Header="_File">
                <MenuItem Header="_Load" Command="{Binding LoadCommand}" Gesture="Ctrl+L"/>
                <Separator/>
                <MenuItem Header="_Quit" Command="{Binding QuitCommand}" Gesture="Ctrl+Q"/>
            </MenuItem>
            <MenuItem Header="_Edit">
                <MenuItem Header="_New Image" Command="{Binding NewImageCommand}" Gesture="Ctrl+N"/>
                <MenuItem Header="_Preferences..." Command="{Binding PreferencesCommand}" Gesture="Ctrl+,"/>
            </MenuItem>
            <MenuItem Header="_About">
                <MenuItem Header="_About" Command="{Binding AboutCommand}"/>
            </MenuItem>
        </Menu>

        <!-- MDI Container with Managed Windows -->
        <dock:DockControl x:Name="DockControl"
                          Factory="{Binding Factory}"
                          Layout="{Binding Layout}"
                          EnableManagedWindowLayer="True"
                          ShowDockablePreviewOnDrag="True"
                          DragPreviewOpacity="0.7">
        </dock:DockControl>
    </DockPanel>
</Window>
```

**Responsibilities:**
- Owns the `DockControl` from `Dock.Avalonia` which serves as the MDI container
- Manages a `Dock.Model.Core.IDockFactory` to create document windows (`ProportionalDock` for tabbed groups, `DocumentDock` for documents)
- Maintains `ObservableCollection<IDockable>` for open documents
- Handles menu actions (Load, Quit, New Image, Preferences, About)
- Tracks unsaved state across all document view models
- On Quit: iterate all documents, if any `IsDirty`, show confirmation
- On Load: create new document via factory, load image+prompt into it, add to layout
- Configure `DockSettings.UseManagedWindows = true` and `DockSettings.EnableWindowMagnetism = true` at startup

**MDI Document Structure:**
Each image document is a `ManagedDockWindowDocument` (implements `IMdiDocument`) wrapping an `ImageDocumentViewModel`. The managed window has:
- **Draggable titlebar** with document title, minimize/maximize/close buttons
- **Free-floating** — can be positioned anywhere in the main window's client area (not restricted to edges)
- **Z-order management** — clicking brings to front; supports cascade/tile via `MdiLayoutHelper`
- **Tab groups** — dragging one window onto another's tab area creates a tab group
- **Persistable state** — position, size, and dock state can be saved/restored
- **Keyboard focus** — each managed window handles its own focus scope

**Key Dock Settings (set in App.axaml.cs OnFrameworkInitializationCompleted):**
```csharp
DockSettings.UseManagedWindows = true;              // Enable in-app floating windows
DockSettings.EnableWindowMagnetism = true;          // Snap windows together when dragging near each other
DockSettings.BringWindowsToFrontOnDrag = true;      // Auto-bring dragged window to front
DockSettings.ShowDockablePreviewOnDrag = true;      // Show dock preview overlay
DockSettings.DragPreviewOpacity = 0.7;              // Semi-transparent drag preview
```

The `DockControl` template must include a `ManagedWindowLayer` named `PART_ManagedWindowLayer` to host the floating windows.

**ImageCanvas (custom control for rendering):**
- Extends `Control` from Avalonia
- Overrides `protected override void Render(DrawingContext context)`
- Draws the stored `Bitmap` via `context.DrawImage(bitmap, sourceRect, destRect)` or fills black background if null
- Exposes property: `Bitmap? CurrentImage` (with `InvalidateVisual()` call in setter to trigger re-render)

**HistoryPanel:**
- `ScrollViewer` wrapping an `ItemsControl` with `StackPanel` ItemsPanel (vertical)
- Each item is a Border containing an Image thumbnail (~160px wide) + timestamp
- DataTemplate binds to `GenerationRecordViewModel` with `Thumbnail` (Bitmap) and `Timestamp`
- On click: fires `RestoreRecordCommand` to parent ViewModel
- Highlight the currently-displayed record via `IsSelected` property

## 4. Provider-Agnostic API Architecture

The application uses a **provider abstraction** so users can use OpenRouter (default) or any OpenAI-compatible API (Ollama, LM Studio, LocalAI, custom endpoints).

### 4.1 Provider Abstraction

```csharp
// Interface for AI image generation providers
public interface IImageGenerationProvider
{
    string Name { get; }
    string BaseUrl { get; }
    bool RequiresApiKey { get; }

    // Model discovery
    Task<List<ProviderModelInfo>> ListModelsAsync(string? apiKey = null, CancellationToken ct = default);

    // Image generation
    Task<byte[]> GenerateImageAsync(string prompt, int width, int height, string model, string? apiKey, CancellationToken ct);

    // Chat completion (for prompt generation & image-to-prompt)
    Task<string> ChatCompletionAsync(List<ChatMessage> messages, string model, string? apiKey, CancellationToken ct);

    // Vision chat completion (image-to-prompt)
    Task<string> VisionChatCompletionAsync(string prompt, byte[] imageBytes, string model, string? apiKey, CancellationToken ct);
}

// Model info returned by provider
public class ProviderModelInfo
{
    public string Id { get; set; } = string.Empty;
    public string Name { get; set; } = string.Empty;
    public ModelCapabilities Capabilities { get; set; } = new();
    public ModelPricing? Pricing { get; set; }
}

public class ModelCapabilities
{
    public bool SupportsImageGeneration { get; set; }
    public bool SupportsVision { get; set; }
    public bool SupportsChat { get; set; }
    public List<string> SupportedResolutions { get; set; } = new();
    public List<string> SupportedAspectRatios { get; set; } = new();
}

public class ModelPricing
{
    public decimal? PerImage { get; set; }
    public decimal? PerMegapixel { get; set; }
    public decimal? PerToken { get; set; }
    public string? Currency { get; set; } = "USD";
}

public class ChatMessage
{
    public string Role { get; set; } = "user";
    public string Content { get; set; } = string.Empty;
    public List<ChatImageContent>? Images { get; set; }
}

public class ChatImageContent
{
    public string Type { get; set; } = "image_url";
    public string ImageUrl { get; set; } = string.Empty; // data URL or https URL
}
```

### 4.2 Provider Implementations

**OpenRouterProvider (default)** — Implements `IImageGenerationProvider`:
- BaseUrl: `https://openrouter.ai/api/v1`
- Uses OpenRouter-specific endpoints (`/images`, `/models` with image filter)
- Handles OpenRouter's specific response formats
- Adds required headers (`HTTP-Referer`, `X-Title`)

**OpenAICompatibleProvider (generic)** — For Ollama, LM Studio, LocalAI, etc.:
- BaseUrl: configurable (e.g., `http://localhost:11434/v1` for Ollama)
- Uses standard OpenAI-compatible endpoints (`/images/generations`, `/chat/completions`, `/models`)
- No special headers required
- Simpler model filtering (checks model capabilities from response)

## 5. OpenRouter API Reference (Default Provider)

### 5.1 API Base Configuration

- **Base URL:** `https://openrouter.ai/api/v1`
- **Authentication:** Bearer token via `Authorization: Bearer <api-key>` header
- **Referer header:** Required by OpenRouter — use `https://localhost/` or the app name
- **X-Title header:** `AI Image Generator` (identifies app to OpenRouter)
- **All calls** go through `OpenRouterProvider` which implements `IImageGenerationProvider`

### 5.2 List Models

**Endpoint:** `GET /v1/models`

This endpoint returns all available models. We filter client-side for models that support image generation (checking `model.supports.image_generation`) or vision (checking `model.supports.vision`).

**Response format (simplified):**
```json
{
  "data": [
    {
      "id": "stabilityai/stable-diffusion-3.5",
      "name": "Stable Diffusion 3.5",
      "architecture": { "modality": "text-to-image" },
      "pricing": { "image": 0.004 },
      "supports": { "image_generation": true, "vision": false }
    },
    ...
  ]
}
```

### 5.3 Image Generation

**Endpoint:** `POST /v1/chat/completions` (OpenRouter uses chat completion format for image gen)

OpenRouter uses the OpenAI-compatible chat completion format even for image generation. The generation model is specified in the model field.

**Request:**
```json
{
  "model": "stabilityai/stable-diffusion-3.5",
  "messages": [
    {
      "role": "user",
      "content": [
        { "type": "text", "text": "Generate an image of a cat on a train" }
      ]
    }
  ],
  "response_format": {
    "type": "image"
  }
}
```

**Alternative / preferred approach:** Some OpenRouter image models use the standard chat endpoint but return base64-encoded images in the response content, or use the `/v1/images/generations` endpoint (OpenAI-compatible).

**Response:**
```json
{
  "id": "gen-xxx",
  "choices": [
    {
      "message": {
        "content": "data:image/png;base64,iVBORw0KGgo...",
        "role": "assistant"
      }
    }
  ],
  "usage": { "cost": 0.004 }
}
```

The service extracts the base64 data, decodes it to bytes, and constructs an Avalonia `Image` object.

### 5.4 Chat Completion (for Prompt Generation & Image-to-Prompt)

**Endpoint:** `POST /v1/chat/completions`

**Request (Prompt Gen):**
```json
{
  "model": "openai/gpt-4o-mini",
  "messages": [
    {
      "role": "system",
      "content": "You are a creative prompt engineer. Generate a single, detailed image-generation prompt based on the following parameters. Output ONLY the prompt text, no introduction or explanation."
    },
    {
      "role": "user",
      "content": "Humour: Light-hearted\nStyle: Cartoon\nTopic: Trains\nColour: Vivid\nTime of Day: Morning\nMood: Joyful"
    }
  ]
}
```

**Request (Image-to-Prompt):**
```json
{
  "model": "openai/gpt-4o",
  "messages": [
    {
      "role": "user",
      "content": [
        { "type": "text", "text": "Describe this image in detail as a prompt for an image generation model." },
        { "type": "image_url", "image_url": { "url": "data:image/png;base64,iVBOR..." } }
      ]
    }
  ]
}
```

### 5.5 Pricing Retrieval

The model listing endpoint includes `pricing` for each model. For image models:
```json
"pricing": { "image": 0.004, "per_image": 0.004 }
```
For chat models:
```json
"pricing": { "prompt": 0.00001, "completion": 0.00004 }
```

These prices are shown in the ModelBrowserDialog as formatted strings.

## 5. User Interface Flows

### 5.1 New Image Flow
1. User clicks `Edit > New Image` (or `Ctrl+N`)
2. MainWindow instantiates a new `ImageDocumentViewModel`
3. ImageDocument appears as a floating managed window in the MDI container
4. Canvas shows black fill
5. History panel shows "(no generations yet)" text
6. Width defaults to 1024, Height defaults to 1024
7. Prompt textarea is empty

### 5.2 Generate Image Flow
1. User enters prompt, adjusts width/height
2. User clicks `Generate`
3. Generate button is disabled and shows "Generating..." text
4. Service calls OpenRouter API with the prompt and dimensions
5. On success:
   - Response image is decoded to Avalonia Image
   - A new `GenerationRecord` is created with image, prompt, dimensions, timestamp
   - Record is added to `history` list
   - Canvas updates to show the new image
   - History panel updates: new thumbnail prepended/added, all thumbnails refreshed
   - `isDirty` flag set to true
   - Generate button re-enabled
6. On error:
   - Error message displayed in a status bar or popup
   - Generate button re-enabled

### 5.3 History Navigation Flow
1. User clicks a thumbnail in the HistoryPanel
2. ImageWindow `RestoreRecord()` is called
3. Canvas displays the selected record's image
4. Prompt textarea is set to the record's prompt
5. Width/Height inputs are set to the record's dimensions
6. The selected thumbnail is highlighted

### 5.4 Save Flow
1. User clicks `Save`
2. If current record is null or generation is still in progress, do nothing (or beep)
3. A `FileChooser` save dialog opens with default filename `Generated-YYYYMMDD-HHmmSS.png`
4. User selects folder and confirms
5. Image is written as PNG to the chosen path
6. The prompt text is written to `{filename}.png.prompt` (e.g. `Generated-20261111-225900.png.prompt`)
7. The record's `saved` flag is set to true
8. Success notification (brief toast or status bar message)

### 5.5 Load Flow
1. User clicks `File > Load` (or `Ctrl+L`)
2. `FileChooser` open dialog for `*.png` files
3. User selects a PNG file
4. Image bytes are read into memory
5. The service checks for companion file `{selected}.prompt`
6. If prompt file exists, its content is read as the prompt text; otherwise prompt is empty
7. MainWindow creates a new `ImageDocumentViewModel`
8. A `GenerationRecord` is created with the loaded data (marked as saved=true)
9. Record placed in the window's history list
10. Canvas displays image, prompt filled, dimensions honor original image size
11. Window added to MDI

### 5.6 Quit Flow
1. User clicks `File > Quit` (or `Ctrl+Q` / window close button)
2. MainWindow iterates all `ImageDocumentViewModel` instances calling `IsDirty`
3. If any window has `isDirty == true`:
   - Modal confirmation dialog appears: "Unsaved images, really quit?" with [Yes] [No]
   - Yes → application exits
   - No → dialog dismissed, nothing happens
4. If no dirty windows, application exits immediately

### 5.7 Preferences Flow
1. User clicks `Edit > Preferences`
2. `PreferencesDialog` opens as a modal window
3. Fields:
   - **Theme:** `ComboBox` with options **"Dark", "Light", "System"** (default: **"System"**). Changing the selection previews the theme immediately; **Save** commits it, **Cancel** reverts.
   - **OpenRouter API Key:** `PasswordField` (masked input)
   - **Image Generation Model:** `TextField` + `[Show All Models]` button
   - **Vision/Image Parsing Model:** `TextField` + `[Show All Models]` button
4. `[Show All Models]` (for image gen) → calls OpenRouter to list models → opens `ModelBrowserDialog` filtered to `image_generation` models → user selects one → model name populates the text field
5. `[Show All Models]` (for vision) → same but filtered to `vision` models
6. `[Save]` / `[Cancel]` buttons at bottom
7. On **Save**: all preferences (including the selected theme) are committed and written to the config file via `PreferencesService`; the dialog closes; the new theme is applied immediately to the whole application
8. On **Cancel**: changes are discarded; the previous theme (if previewed) is reverted; nothing is written

**Theme handling details:**
- Theme value maps to Avalonia's `RequestedThemeVariant`: `"Dark"` → `ThemeVariant.Dark`, `"Light"` → `ThemeVariant.Light`, `"System"` → `ThemeVariant.Default` (follows the OS).
- The theme is applied on the application root (`Application.Current.RequestedThemeVariant`), so all windows, dialogs and MDI documents follow it.
- On startup the saved theme is loaded from the config file **before** the main window is created, so there is no flash of the wrong theme.
- The theme choice lives in the same config file as the rest of the preferences (see 6.1) and is persisted only when the user presses Save.

### 5.8 Model Browser Flow
1. Called from Preferences
2. Opens as a modal resizable window
3. Loading indicator while API call is in flight
4. Results displayed in a `TableView` with columns: **Model Name**, **Model ID**, **Pricing per image** (or per token)
5. User can scroll through list
6. Buttons: `[Select]` and `[Cancel]`
7. Select → the selected model's ID is returned and placed in the Preferences text field
8. If API call fails → error message shown, dialog remains openable for retry

### 5.9 About Dialog
- `Window` with `Title: "About AI Image Generator"`
- Content:
  - App name: **"AI Image Generator"**
  - Version: "1.0.0"
  - Description: "An AI image generation desktop application powered by OpenRouter"
  - Button: `[OK]` to dismiss

## 6. Data Persistence

### 6.1 Preferences Storage

**Location:** The preferences config file is stored **in the same folder as the program executable** (not the user's app-data directory). This keeps the config portable alongside the app:

- `<executable directory>/preferences.json` — resolved via `AppContext.BaseDirectory` at runtime (works when running from `dotnet run` too, where it lands in `bin/Debug/net10.0/`).

**Format:**
```json
{
  "selectedProviderId": "openrouter",
  "openRouterApiKey": "sk-or-v1-...",
  "openRouterGenerationModel": "stabilityai/stable-diffusion-3.5",
  "openRouterVisionModel": "openai/gpt-4o",
  "customProviderName": "Custom",
  "customProviderBaseUrl": "http://localhost:11434/v1",
  "customProviderApiKey": "",
  "customGenerationModel": "",
  "customVisionModel": "",
  "theme": "System"
}
```

- **`theme`** values: `"Dark"`, `"Light"`, or `"System"` (default when absent).
- The file is written whenever the user presses **Save** in the Preferences dialog, and **only** then — no intermediate writes while editing.
- The API key should be stored with at-rest obfuscation (simple base64 or platform keychain if available). For simplicity in v1, store as plaintext JSON with basic XOR/base64 obfuscation optional.

### 6.2 Image Save Format

- Primary file: `Generated-YYYYMMDD-HHmmSS.png`
- Companion file: `Generated-YYYYMMDD-HHmmSS.png.prompt`
  - Contains the raw prompt text (UTF-8 encoded)
  - No additional metadata, wrapping, or structure — just the prompt as plain text
  - Example content: `"A whimsical cartoon of a train made of bread, travelling through a forest of giant vegetables, colourful, morning light"`

## 7. Threading & Concurrency

### 7.1 Async API Calls

All HTTP calls to OpenRouter must run off the UI thread:

```csharp
// Pattern for image generation — using AsyncRelayCommand (CommunityToolkit.Mvvm)
[AsyncRelayCommand]
private async Task GenerateImage()
{
    IsGenerating = true;

    try
    {
        // HttpClient is inherently async I/O — no need for Task.Run
        var imageBytes = await _openRouterService.GenerateImageAsync(
            _preferences.ApiKey,
            _preferences.GenerationModel,
            CurrentPrompt,
            ImageWidth,
            ImageHeight);

        // We're back on the UI thread — safe to update properties
        var record = new GenerationRecord
        {
            ImageData = imageBytes,
            Prompt = CurrentPrompt,
            Width = ImageWidth,
            Height = ImageHeight,
            Timestamp = DateTime.Now,
            IsSaved = false
        };

        History.Add(record);
        CurrentRecord = record;
        CurrentImageBytes = imageBytes;
        IsDirty = true;
    }
    catch (Exception ex)
    {
        // Show error dialog
        await _dialogService.ShowErrorAsync("Generation failed: " + ex.Message);
    }
    finally
    {
        IsGenerating = false;
    }
}
```

### 7.2 UI Thread Safety
- All UI mutations (updating canvas, history panel, text fields, button states) must go through `Avalonia.Application.Instance.InvokeLater()` or `Platform.RunLater()`
- Heavy image processing (thumbnail generation, base64 encode/decode) can stay on the background thread but must not touch UI objects
- Thumbnails: generate scaled-down versions of images on the background thread, then `InvokeLater` to update the history panel

## 8. Thumbnail Generation

To show thumbnails in the history panel:

```csharp
// Generate thumbnail from image bytes — off the UI thread
public static Bitmap? CreateThumbnail(byte[] imageBytes, int maxWidth = 120)
{
    try
    {
        using var ms = new MemoryStream(imageBytes);
        var bitmap = new Bitmap(ms);

        // Calculate scaled dimensions preserving aspect ratio
        double scale = (double)maxWidth / bitmap.PixelSize.Width;
        int thumbWidth = maxWidth;
        int thumbHeight = (int)(bitmap.PixelSize.Height * scale);

        // Create scaled bitmap (available on Avalonia Bitmap)
        return bitmap.CreateScaledBitmap(new PixelSize(thumbWidth, thumbHeight), BitmapInterpolationMode.HighQuality);
    }
    catch
    {
        return null; // Return null if thumbnail generation fails
    }
}
```

Thumbnails should be generated asynchronously after each generation completes, before updating the UI.

## 9. Unsaved Changes Tracking

Each `ImageWindow` tracks its dirty state:

```csharp
// In ImageWindowViewModel.cs
public partial class ImageWindowViewModel : ObservableObject
{
    [ObservableProperty]
    private bool _isDirty;

    // Called when a new generation is made
    private void OnGenerationCreated()
    {
        IsDirty = History.Any(r => !r.IsSaved);
    }

    // Called when the user saves the current record
    public void MarkSaved()
    {
        if (CurrentRecord != null)
        {
            CurrentRecord.IsSaved = true;
            // Re-check: if all records are saved, IsDirty = false
            IsDirty = History.Any(r => !r.IsSaved);
        }
    }
}

// In MainWindowViewModel.cs
public bool HasUnsavedWindows()
{
    return _openViewModels.Any(vm => vm.IsDirty);
}
```
